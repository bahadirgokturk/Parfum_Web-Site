# Temel AI ve Yazılım Terimleri

Bu sözlük, proje toplantılarında ve geliştirme görevlerinde kullanılan terimlerin ortak anlamını belirler.

| Terim | Türkçesi | Bu projedeki anlamı |
| --- | --- | --- |
| Context | Bağlam | AI'ın görevi yaparken bildiği ilgili proje bilgileri |
| Context Engineering | Bağlam mühendisliği | Doğru bilgiyi doğru zamanda ve uygun miktarda AI'a verme |
| Prompt Engineering | Prompt/istem mühendisliği | Bir isteği açık, sınırlı ve doğrulanabilir ifade etme |
| Instructions | Talimatlar | AI'ın uyması gereken kurallar |
| System Instructions | Sistem talimatları | Kullanıcı isteğinden daha temel davranış ve güvenlik kuralları |
| Project Instructions | Proje talimatları | Bu depoya özel, `AGENTS.md` içindeki kalıcı kurallar |
| Coding Guidelines | Kodlama ilkeleri | Kod kalitesi, okunabilirlik, test ve hata yönetimi beklentileri |
| Conventions | Teamüller / standartlar | Mevcut isimlendirme, klasörleme ve uygulama biçimleri |
| Constraints | Kısıtlamalar | Bir görevde yapılmaması veya korunması gerekenler |
| Guardrails | Koruyucu sınırlar | Riskli, yetkisiz veya yanlış davranışı engelleyen kontroller |
| Requirements | Gereksinimler | Özelliğin ne yapması gerektiği |
| Acceptance Criteria | Kabul kriterleri | Gereksinimin karşılandığını kanıtlayan gözlenebilir sonuçlar |
| Definition of Done | Tamamlanma tanımı | Bir işin gerçekten tamamlanmış sayılması için tüm koşullar |
| Architecture | Mimari | Sistemin parçaları, sorumlulukları ve aralarındaki sınırlar |
| Design Pattern | Tasarım kalıbı | Tekrarlanan bir tasarım problemine bilinen çözüm yaklaşımı |
| Codebase | Kod tabanı | Depodaki kaynak kodların ve ilgili yapılandırmanın bütünü |
| Dependency | Bağımlılık | Projenin kullandığı haricî paket veya servis |
| Refactoring | Yeniden düzenleme | Gözlenen davranışı değiştirmeden kod yapısını iyileştirme |
| Regression | Geriye dönük bozulma | Yeni değişikliğin daha önce çalışan davranışı bozması |
| Regression Test | Regresyon testi | Mevcut davranışların hâlâ çalıştığını kontrol eden test |
| Unit Test | Birim testi | Tek bir fonksiyon, bileşen veya küçük davranışı izole test etme |
| Integration Test | Entegrasyon testi | Birden fazla parçanın birlikte doğru çalışmasını test etme |
| End-to-End Test | Uçtan uca test | Gerçek kullanıcı akışını baştan sona test etme |
| Edge Case | Uç durum | Normal akış dışındaki sınır veya istisna durumu |
| Error Handling | Hata yönetimi | Hataları güvenli, anlaşılır ve kurtarılabilir biçimde ele alma |
| Validation | Doğrulama | Girdinin beklenen biçim ve iş kurallarına uygunluğunu kontrol etme |
| Logging | Loglama | Tanılama ve operasyon için güvenli sistem olayları kaydetme |
| Observability | Gözlemlenebilirlik | Log, metrik ve izlerle sistemin iç durumunu anlayabilme |
| Maintainability | Sürdürülebilirlik | Kodun gelecekte güvenle anlaşılıp değiştirilebilmesi |
| Scalability | Ölçeklenebilirlik | Kullanıcı ve işlem yükü arttığında sistemin uyum sağlayabilmesi |
| Technical Debt | Teknik borç | Kısa vadeli kolaylık uğruna geleceğe aktarılan geliştirme maliyeti |
| Legacy Code | Eski kod | Daha önce yazılmış, mevcut davranışı ve kullanıcıları korunması gereken kod |
| Breaking Change | Kırıcı değişiklik | Mevcut API, veri veya kullanımı uyumsuz hâle getiren değişiklik |
| Backward Compatibility | Geriye uyumluluk | Eski kullanımın yeni sürümde çalışmaya devam etmesi |
| Minimal Diff | Minimum değişiklik | Gereksinimi karşılayan en küçük odaklı kod değişikliği |
| Scope | Kapsam | Görevin dahil ettiği davranış ve sistem sınırları |
| Out of Scope | Kapsam dışı | Bu görevde bilerek yapılmayacak işler |
| Root Cause | Kök neden | Belirtinin arkasındaki asıl problem |
| Code Review | Kod incelemesi | Değişikliği doğruluk, risk, kalite ve güvenlik açısından değerlendirme |
| Self Review | Öz inceleme | Geliştiricinin veya AI'ın kendi değişikliğini teslimden önce sorgulaması |
| Data Flow | Veri akışı | Verinin sisteme girişinden depolama ve çıktıya kadar izlediği yol |
| Trust Boundary | Güven sınırı | Verinin farklı güven seviyeleri arasında geçtiği ve doğrulanması gereken nokta |
| Idempotency | Tekrarlama güvenliği | Aynı isteğin tekrarının fazladan sipariş, ödeme veya stok hareketi oluşturmaması |
| Transaction | İşlem bütünlüğü | Bir grup veri değişikliğinin ya tamamen yapılması ya da tamamen geri alınması |
| Prompt Injection | Prompt enjeksiyonu | Kullanıcı/veri içindeki metinle AI talimatlarını ele geçirme girişimi |
| Runtime Validation | Çalışma zamanı doğrulaması | Gerçek verinin program çalışırken şemaya uygunluğunu kontrol etme |
